# 社内ネットワークトポロジービューワ 要件定義

- プロジェクト名：tylan
- 作成日：2026-11-05
- 文書バージョン：0.2（2026-11-05：保存方式を「JSONファイルを直接編集・自動保存」に変更）

## 1. 目的と成果物

現地の機器・配線・設定・管理状態を把握し、ネットワーク構成図と資産台帳の初版を作る。調査途中の不明点も保存し、構成図・台帳・監査結果を同じデータから参照できるようにする。

成果物は、共有フォルダから開ける閲覧用HTML、編集用HTML、復元可能な正本JSON、資産台帳・監査結果・対応事項のCSVとする。編集用HTMLは「JSONファイルを直接編集するエディター」とし、監査ごとのJSONを作成・編集する。利用者のPCへの実行環境の導入や、Webサーバーの運用を不要とする。

### 1.1 ユーザー指定の必須条件

| ID      | 要件                                                                                                |
| ------- | --------------------------------------------------------------------------------------------------- |
| MUST-01 | 社内ファイルサーバーの共有フォルダに配置して利用できる。ホスティングしない。                        |
| MUST-02 | 編集画面はSvelteで実装し、作成・参照・更新・削除（CRUD）を安全に行える。                            |
| MUST-03 | ビューワはxyflowのSvelte版（`@xyflow/svelte` / Svelte Flow）で、美しく読みやすい構成図を表示する。  |
| MUST-04 | 提示されたネットワーク監査項目を扱い、判定を「問題なし／要対応／未確認／対象外」の4値から選択する。 |
| MUST-05 | 現地調査から構成図と資産台帳の初版作成までを一連の作業として支援する。                              |

### 1.2 初版の前提と対象外

- Windowsの社内管理端末と、社内標準のMicrosoft Edgeを第一対象とする。Chromeも確認対象とし、正式な対応バージョンは実装着手時に固定する。
- UNCパス（例：`\\fileserver\network\tylan\`）と割り当てドライブの両方で確認する。ブラウザーは`file://`でHTMLを開く。
- 初版は1プロジェクト内に複数拠点を保持し、同一プロジェクトの編集者は同時に1名とする。閲覧は複数人で行える。
- 実機への設定投入、SNMP・ping・LLDP等による自動探索、常時監視、通信キャプチャ、稼働率の測定、AD認証連携、リアルタイム共同編集は初版の対象外。
- 現地で取得した情報を人が登録する。線が描かれていることは実通信や疎通を保証しない。
- 現地写真や設定ファイルの添付は初版に含めず、証跡の説明と管理番号・保管先の文字列を記録する。
- サーバー認証、改ざん不能な監査ログ、ファイルの排他ロックが必要になった場合は、ホスティングなしという制約も含めて別途方式を見直す。

## 2. 配布・起動・保存方式

### 2.1 基本方式

通常のVite開発環境と、利用者へ配布する成果物を分ける。配布物はJavaScript・CSS・アイコン等を内包した単体HTMLとし、外部モジュール・CDN・Webフォント・APIへアクセスせずに動作する。

`file://`で外部JavaScriptモジュールを読み込むとCORSの制約を受けるため、通常のViteビルドを置くだけでは成立を保証できない。[MDNのモジュール説明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)を踏まえ、配布物では外部`import`、動的チャンク取得、起動時のJSONの`fetch`を不要にする。`base: './'`の設定のみで完了とはしない。具体的なバンドル方式は技術検証で確定する。

| ファイル       | 役割・利用方法                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| `editor.html`  | 編集ツール。データを内包せず起動し、正本JSONを新規作成または開いて直接編集・自動保存する。               |
| `network.json` | 編集の正本。資産、接続、ネットワーク設定、監査、対応事項、図の配置を保存する。                           |
| `viewer.html`  | 編集ツールから生成する閲覧用スナップショット。表示対象のデータとビューワを内包し、開くだけで閲覧できる。 |
| 監査ごとのJSON | 例：`network-2026.json`。前回分は前回のJSONとして残り、そのまま世代の記録になる。                        |

閲覧用HTMLと正本JSONは別成果物である。正本を更新しても配布済みの閲覧用HTMLは自動更新されない。閲覧用HTMLにはプロジェクト名、データ版、調査基準日、生成日時、アプリ版を表示し、再公開後はファイルを開き直す。

### 2.2 作成・編集・保存

編集用HTMLは開くと開始画面を表示し、次のいずれかでJSONファイルを用意するまで編集できない。

- **新しいJSONを作る**：保存先とファイル名を選び、空のプロジェクトを即座にファイルとして作る。
- **前回のJSONをもとに作る**：前回のファイルを選び、続けて新しい保存先を選ぶ。機器・配線・過去の監査結果を引き継ぎ、元のファイルは変更しない。
- **既存のJSONを開く**：作成済みのファイルの続きを編集する。

ファイルの選択と保存にはEdge/Chromeの[File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)を使う。`file://`で開いたページでも利用できることを確認済み。利用者が選んだファイルだけを扱い、共有フォルダの自動走査を行わない。

確定した変更は約1秒後に、開いているJSONへ自動保存する。Ctrl+Sまたは「今すぐ保存」で即時保存できる。画面には保存済み・保存中・未保存・保存失敗を区別して表示する。保存に失敗した場合は成功を装わず、変更をメモリー上に保持したまま再保存を案内する。

保存の直前にファイルの更新日時を確認し、開いた時点または前回保存した時点から別の場所で変更されていれば自動保存を止める。利用者は「ファイルの内容を読み込み直す」か「この画面の内容で上書きする」を選ぶ。これは同時編集を可能にする仕組みではなく、気付かずに上書きすることを防ぐ安全策である。

閲覧用HTMLとCSVは保存先を選んで保存する。PNGはブラウザーのダウンロードとする。File System Access APIを使えないブラウザーでは、従来どおりJSONの読込とダウンロードによる書き出しで動作する。

### 2.3 共有フォルダでの運用

```text
\\fileserver\network\tylan\
  tools\editor.html           # アプリ管理者のみ更新
  working\network-2026.json   # 監査ごとの正本。編集ツールが直接保存する
  published\viewer.html       # 閲覧者には読み取り権限
  archive\...                 # 過去のJSONと閲覧用HTML
```

1. 編集担当者が担当を宣言する。同時編集を運用上避ける。
2. 監査を始めるときは、編集用HTMLで「前回のJSONをもとに作る」（初回は「新しいJSONを作る」）を選び、`working\`に今回分のJSONを作る。
3. 調査結果・資産・接続等を編集する。変更は自動でJSONへ保存される。
4. 公開前に検証結果と公開範囲をプレビューし、閲覧用HTMLを`published\`へ保存する。旧い閲覧用HTMLは`archive\`へ退避する。
5. 公開した閲覧用HTMLを開き直し、データ版と内容を確認する。

`revision`は保存ごとに増える。閲覧用HTMLには生成元のJSONの版を表示し、JSONとHTMLの版の対応を確認できるようにする。更新日時の確認は上書き事故を防ぐ補助であり、なりすましや同時編集を防ぐ仕組みとは扱わない。

### 2.4 権限と安全性の境界

| 利用者           | アプリでの作業                                     | ファイルサーバー側の制御           |
| ---------------- | -------------------------------------------------- | ---------------------------------- |
| 閲覧者           | 公開済み構成図、公開対象の台帳・監査結果を参照     | `published`の読み取りのみ          |
| 調査・編集担当者 | 担当データのCRUD、検証、候補の書き出し             | `working`の必要範囲へのアクセス    |
| 公開・管理担当者 | 候補確認、正本反映、公開、バックアップ、アプリ更新 | `published`・`archive`等の更新権限 |

役割は業務上の区分であり、静的HTML内のログインや編集ボタンの非表示を認可とは扱わない。アクセス制御は共有・NTFS権限と端末管理で実施する。閲覧用HTML内のデータは閲覧者が取り出せるため、非表示項目も秘密にはできない。公開しない項目はHTML生成時点で除外する。閲覧権限を持つ利用者によるコピーの回収・失効は初版では扱わない。

## 3. 業務フローと画面

### 3.1 調査から公開まで

プロジェクト・拠点作成 → 監査回次作成 → 機器・設置場所登録 → ポート・配線登録 → IP・DHCP・DNS・無線設定登録 → 監査判定・証跡登録 → 対応事項整理 → 図と台帳の整合確認 → 正本書き出し → 閲覧用HTML生成・共有。

実機情報が未確認でも、仮の機器・接続を作れる。「不明」「推定」を明示し、推測で型番・IP・接続先を補完しない。未確認を含む初版の公開を許容し、その件数・内容が分かるようにする。

### 3.2 必要画面

| 画面               | 主な内容                                                                     |
| ------------------ | ---------------------------------------------------------------------------- |
| 開始・プロジェクト | 新規作成、JSON読み込み、拠点一覧、データ版、検証結果、未書き出し状態         |
| トポロジービューワ | 大きな構成図、検索・絞り込み、凡例、選択要素の詳細、調査状況                 |
| 機器・資産台帳     | 一覧・検索・並び替え、詳細、作成・更新・削除、関連ポート・接続・監査への移動 |
| ポート・接続編集   | 接続端点、媒体、速度、ポート用途、確認状況、図上での接続操作                 |
| ネットワーク設定   | サブネット、GW、DHCP、固定IP、DNS、SSID・認証方式・分離状況                  |
| 監査一覧・詳細     | 回次、項目番号、対象、4値判定、確認結果、問題点、証跡、確認者・確認日        |
| 対応事項一覧       | 対応対象、優先度、担当者、期限、進捗、関連する監査結果                       |
| 検証・書き出し     | エラー／警告一覧、公開対象の確認、JSON・閲覧HTML・CSV出力                    |

各編集画面は「一覧 → 詳細 → 編集 → 検証 → 確定」の流れを揃える。構成図から資産・接続・監査へ、一覧から該当ノードへ相互に移動できるようにする。

## 4. 機能要件

### 4.1 安全なCRUDと入力検証

| ID      | 要件                                                                                                                                                         |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CRUD-01 | 拠点、設置場所、機器、インターフェース／ポート、接続、ネットワーク設定、監査結果、対応事項を作成・参照・更新・削除できる。                                   |
| CRUD-02 | フォームは編集用の値を分離し、確定時にだけ正本の作業データを更新する。キャンセルで元に戻る。                                                                 |
| CRUD-03 | フォーム確定・図上の接続変更・JSON読み込み・全出力で、共通スキーマと参照整合性を検証する。                                                                   |
| CRUD-04 | エラーを項目の近くに日本語で表示し、対象への移動と修正ができる。フォーム入力を失わない。                                                                     |
| CRUD-05 | 削除前に機器名と、関連ポート・接続・監査・対応事項・配置への影響を表示する。参照がある場合は削除を止め、解除・再関連付けを案内する。暗黙の連鎖削除をしない。 |
| CRUD-06 | 使用終了した機器は「撤去済み／未使用」として保持できる。物理削除と状態変更を区別する。                                                                       |
| CRUD-07 | 直前の確定変更・削除を取り消せる。JSONの再読み込みやアプリ終了をまたぐUndoは対象外。                                                                         |
| CRUD-08 | 入力中・未保存・保存中・保存済み・保存失敗を区別して表示する。確定した変更は開いているJSONへ自動保存し、未保存の変更がある状態での画面離脱は警告する。       |
| CRUD-09 | 不正JSON、未対応スキーマ版、容量超過、参照不整合の読込失敗時は、現在の作業データを一切置き換えない。検証成功後に一括置換する。                               |

初版はJSONの全件読み込み・全件書き出しとし、差分マージ・CSVインポートを行わない。フィルターで隠れたデータも正本JSONには保持する。

### 4.2 ビューワと図の編集

| ID      | 要件                                                                                                                                                         |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| VIEW-01 | サービスアダプタ → スイッチ → AP・端末等を俯瞰できる。サービスアダプタ、スイッチ、AP・中継器、PC、プリンタ、NAS、カメラ、勤怠、IoT、その他／不明を表現する。 |
| VIEW-02 | ノードに名称・種別・主要IP・設置場所・確認状況を表示する。詳細パネルで型番・所有／管理・監査を参照する。情報が多い場合はズームに応じて表示量を減らす。       |
| VIEW-03 | 接続線に両端ポート、媒体（銅線／光／無線／不明）、速度、VLAN等を必要に応じて表示する。物理接続と論理的な所属・関連を線種と凡例で区別する。                   |
| VIEW-04 | パン、ズーム、全体表示、ミニマップ、検索結果へのフォーカス、選択ノードの隣接接続の強調を備える。                                                             |
| VIEW-05 | 拠点、設置場所、機器種別、監査判定、確認状況、VLAN／SSIDで絞り込める。該当外の隣接ノードは必要に応じて薄く残し、非表示の接続があることを示す。               |
| VIEW-06 | 編集時はドラッグ配置、整列、自動レイアウト、配置固定ができる。レイアウト更新で固定ノードを動かさず、未固定ノードの再配置前に確認・取り消しができる。         |
| VIEW-07 | 図の配置・表示設定を保存し、再読込時に復元する。資産や接続を削除せずに図からのみ除外できる。                                                                 |
| VIEW-08 | 閲覧用HTMLでは機器・接続・保存配置を変更できない。パン・ズーム・検索は可能とする。                                                                           |
| VIEW-09 | 推定接続・接続先不明・用途不明を破線や記号で表し、確定した接続と見分けられる。稼働中を示すアニメーションは観測情報がない限り付けない。                       |
| VIEW-10 | 構成図をPNGとして出力できる。図名、拠点、データ版、凡例を含め、全体図／表示範囲を選べる。ブラウザーの印刷からPDFに残せる印刷表示も備える。                   |

美しさは装飾量ではなく、機器階層、線の追跡しやすさ、余白、文字の可読性で評価する。初期表示はサービスアダプタから下流へ揃え、拠点・設置場所をグループ化する。物理配線は双方向を基本とし、配置上の上下を通信方向の矢印として表さない。

白〜淡いグレーを基調に、細い接続線、統一したノード寸法、控えめな影、整った日本語タイポグラフィを採用する。判定色は「問題なし＝緑、要対応＝赤、未確認＝琥珀、対象外＝グレー」を初期案とし、色に加えて文字・記号を必ず表示する。重なりや交差を減らし、詳細ラベルは選択時に展開する。キーボード操作、フォーカス表示、一覧からの代替参照、動きを抑える設定を提供する。

### 4.3 台帳・設定・出力

- **DATA-01**：資産台帳と構成図は同じ機器IDを使う。名称変更・IP変更が両方に反映され、図にない未接続資産も台帳に保持する。
- **DATA-02**：IP/CIDR、デフォルトGW、DHCP配布元・範囲・除外・リース、固定IP、DNS、VLAN、SSID・用途・認証方式・分離状態を構造化して記録する。不明値は未確認として残す。
- **DATA-03**：台帳・ポート・監査結果・対応事項をそれぞれCSV出力する。監査CSVは元の列順を先頭に保ち、拠点・対象・回次・確認者・確認日・証跡等を後続列に付ける。
- **DATA-04**：正本JSONに全データと図配置を保持し、読み込み→編集なしの書き出し→再読込で意味上の情報が欠落しない。PNG・CSV・閲覧用HTMLを編集用正本として扱わない。
- **DATA-05**：閲覧用HTMLは拠点・項目の公開対象をプレビューして生成する。対象外の機器・接続・監査・証跡等を参照関係も含めて除外し、非公開データを隠し属性等に残さない。
- **DATA-06**：初版の標準公開範囲は、選択拠点の構成図、公開用資産項目（名称・種別・型番・IP・設置場所）、監査番号・判定・確認日とする。シリアル、連絡先、自由記述、証跡、対応事項は初期状態で除外し、必要なものを公開担当者が選択する。画面上の検索・フィルターは公開範囲の指定として流用しない。

## 5. ネットワーク監査

### 5.1 判定と記録ルール

| 判定     | 意味・必須記録                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 問題なし | 対象と確認内容を確認し、当該項目について問題を認めなかった。確認結果・確認者・確認日を必須とする。           |
| 要対応   | 問題または対処が必要な状態を確認した。上記に加えて問題点・対応事項を必須とし、対応管理レコードに関連付ける。 |
| 未確認   | 未調査、権限不足、確認不能、判断材料不足。初期値とし、確認を試みた場合は理由・次の確認方法を記録する。       |
| 対象外   | 対象設備・業務が存在しないなどで適用しない。対象外理由・確認者・確認日を必須とする。                         |

判定はネットワークのオンライン／オフライン表示と分離する。「問題なし」はその確認時点・対象・項目についての記録であり、拠点全体の安全性や規格適合を自動認定しない。

監査項目のマスターと、拠点・対象・調査回次ごとの結果を分ける。拠点ごとの20項目を初期生成し、初期判定はすべて未確認とする。複数の機器・SSID・接続に個別確認が必要なら、同じ項目番号で対象別の結果を追加する。拠点の総括と個別結果の関係を保持し、全件の問題なしを自動入力しない。

対象別結果に「要対応」があれば拠点総括を「問題なし／対象外」にできず、「未確認」が残る場合も「問題なし」にできない。集計は初期生成した20項目の総括を分母にし、個別結果の件数を別表示する。未確認と対象外を問題なしに含めない。

### 5.2 初期監査マスター

提示された20項目を初期値とする。元のNo.を維持し、提示されていない9〜11は補完・採番し直しを行わない。

全項目で「判定」「確認結果・現状」「問題点・対応事項」を入力する。追加記録として対象、確認者、確認日、確認方法、証跡、再確認予定を持つ。

| No. | 分類           | 調査項目         | 現地で確認する内容                                                  | 確認方法・記録のヒント                       |
| --- | -------------- | ---------------- | ------------------------------------------------------------------- | -------------------------------------------- |

### 5.3 対応事項と図への反映

- **AUDIT-01**：項目No.、分類、対象、判定、確認結果・現状、問題点・対応事項を一覧・詳細・CSVで追跡できる。
- **AUDIT-02**：要対応から対応事項を作成し、優先度（高／中／低）、担当者、期限、進捗（未着手／対応中／確認待ち／完了／保留）、完了記録を管理する。担当者・期限が未定ならその状態を表示する。
- **AUDIT-03**：対応事項の完了で監査判定を自動的に問題なしへ変えない。再確認の記録によって更新する。
- **AUDIT-04**：機器・接続に紐づく監査判定を図と詳細パネルから確認できる。拠点全体の課題を無関係な全機器に転記しない。
- **AUDIT-05**：図の要約バッジは対象回次の関連結果を「要対応 → 未確認 → 問題なし」の順で表示し、適用対象がすべて対象外のときのみ対象外にする。記録がない場合は「監査記録なし」と表示する。複数判定がある場合は件数も示す。
- **AUDIT-06**：新しい調査回次を作成し、前回結果を参照できる。前回の判定を今回の確認済みとして引き継がず、未確認から開始する。

### 6.2 整合性と不明値

- IDは名称・IPと独立し、名称変更で参照を壊さない。監査No.はマスター内で一意とし、結果のIDとは分ける。
- 不明な値は`null`等で表し、空文字・0・偽のIPで代用しない。未確認、対象外、意図的な未設定を区別する。
- 機器の承認状態（承認済み／非承認／不明）、使用状態（使用中／未使用／撤去済み／不明）、観測状態、監査判定は別属性にする。
- 型、列挙値、文字数、ID重複、参照先、座標の有限値、IPv4／IPv6・CIDR・MACの書式、VLAN範囲等を検証する。
- 存在しない端点、同一ポート自身への接続、重複した同一接続、通常の物理ポートの二重利用はエラーにする。ループ・冗長構成・複数リンクは、異なる有効なポート同士なら記録可能とする。
- DHCPの開始・終了逆転や形式不正はエラーとする。範囲のセグメント外、固定IP重複、DHCPとの重なり、リンクローカルIP等の実環境の異常は警告として保存可能とする。同じIPでも別ネットワークなら重複と断定しない。
- 一般に、壊れたデータ構造は拒否し、調査で見つかった問題のある実環境は記録できる。警告と未確認の存在だけでは書き出しを禁止しない。
- 保存日時はタイムゾーン付きISO 8601、調査日・期限は日付として保持する。画面表示は日本時間を初期値とし、書き出しファイル名には版と日時を含める。
- `schemaVersion`で形式を管理し、未知の将来版は更新を案内して読込拒否する。移行処理を実装する場合は原本を維持し、バックアップと検証を経て新形式へ書き出す。

## 8. 技術方針と既存リポジトリ

現在のリポジトリはSvelte 5、TypeScript、Viteのテンプレートで、`@xyflow/svelte`とZodが導入されている。業務画面、データ保存、配布用の単体HTML生成は未実装である。

- Svelte 5のリアクティビティを用い、フォーム・一覧・詳細・図をコンポーネントに分割する。[Runesの公式説明](https://svelte.dev/docs/svelte/what-are-runes)に沿って状態を扱い、単一の作業データから一覧と図を導出する。
- 業務データ、検証・更新処理、画面状態、図の配置、ファイル入出力を分離する。図ライブラリーの内部状態を正本データにしない。
- 図は[Svelte Flow](https://svelteflow.dev/learn)を使用する。自動レイアウトとPNG出力の実現方式は別途検証し、xyflowだけで全要件を満たすと仮定しない。
- Zodのスキーマと業務上の参照検証を共用し、フォーム以外の読込・図上編集・出力から検証を回避できない構造にする。
- 利用時にSvelteKitのサーバー機能、DB、Node.js、Bun、Pythonを要求しない。開発時のViteサーバーと本番の起動方式を混同しない。
- パッケージ追加やビルド方式の変更は実装段階で判断する。本要件定義の段階ではアプリ本体を変更しない。

## 10. 実装前の検証と未確定事項

### 10.1 実装順序

1. **配布方式の検証**：単体HTML上でSvelte Flow、JSON入出力、データ内包閲覧HTMLの生成、共有からの起動を確認する。社内ポリシーで`file://`の実行が阻害される場合は、設定無効化で回避せず方式を相談する。
2. **データとCRUD**：スキーマ、監査20項目、参照検証、拠点・資産・ポート・接続の編集を実装する。
3. **図と監査**：可読性を整え、図・台帳・監査・対応事項を連動させる。自動レイアウト・PNG出力も共有起動で確認する。
4. **出力と運用**：公開対象の除外、CSV、版管理、バックアップ・復旧手順を仕上げ、受入条件を確認する。

### 10.2 未確定事項と初期方針

以下は要件定義を進めるための仮定であり、必要になった時点で実環境と照合する。

| 確認事項                                     | 初期方針                                              | 確定する時点           |
| -------------------------------------------- | ----------------------------------------------------- | ---------------------- |
| 社内標準OS・ブラウザー・共有HTML実行ポリシー | Windows、Edgeを第一対象。Chromeも確認                 | 配布方式の技術検証前   |
| 同時編集の必要性                             | 同一JSONは1名編集。保存前の更新日時確認で上書きを防止 | 運用開始前             |
| 閲覧者に公開可能な情報                       | DATA-06を初期値とし、生成前に対象項目を確認           | 初回公開前             |
| 対象拠点・機器数・回次の保持規模             | NFR-02の規模を初期目標                                | 性能検証用データ作成前 |
| 未提示の監査No.9〜11                         | 欠番を維持し、内容を創作しない                        | 追加項目の提示時       |
| 証跡本体の保管先・保持期間                   | 既存の社内保管先を参照し、アプリに添付しない          | 運用手順の確定時       |
| 正本・公開・世代管理の担当と権限             | 共有・NTFS権限で担当を分け、旧版を退避                | 初回運用前             |
| バックアップの保持世代・廃棄                 | 社内規則に従い、少なくとも直前版へ戻せる              | 初回運用前             |

同時編集が必須になった場合は、ブラウザー内の見せかけのロックを追加して要件を満たした扱いにせず、保存方式・運用前提を再定義する。
