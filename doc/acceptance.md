# 公開・復旧・受入手順

## 調査用ホストの準備

ソース・編集・自動監査は調査用ホストのローカルで行い、共有フォルダには公開した閲覧用HTMLだけを置く（2026-11-10 方針変更）。

1. 調査用ホストにソースを置き、`bun install --frozen-lockfile`、`bunx playwright install chromium`、`bun run verify` を実行する。
2. `bun run build` で `dist\editor.html` を作り、`launcher\tylan.cmd` から起動できることを確認する。作業データは `data\`（git管理外）に置かれる。`data\` をバックアップ対象に含める。
3. 社内管理者の共有HTML実行ポリシーを確認する（閲覧用HTMLを共有から `file://` で開くため）。ブラウザーの保護設定を無効化して回避しない。

## 日常の更新

1. 編集担当を1名に限定する。
2. 監査の開始時は、`launcher\tylan.cmd` を起動し、前回分を引き継いで今回分のJSON（例：`network-2026.json`）を `data\working\` に作る。前回分のJSONはそのまま残り、記録になる。臨時更新では一覧から今回分を開く。
3. 拠点・資産・配線・設定を登録し、監査回次を作成する。回次は拠点ごとに20項目の未確認から始まる。変更は自動保存される。ヘッダーが「保存済み」であることを確認する。
4. 要対応には問題点・確認者・確認日・対応事項を関連付ける。総括と対象別結果の矛盾は解消する。実環境の異常を示す警告は残してよい。
5. 公開拠点・追加公開項目を選び、プレビューの件数と除外項目を確認する。
6. 「閲覧用HTMLを公開」で `data\published\viewer.html` を更新する（旧版は自動で `data\archive\` へ移る）。
7. `data\published\viewer.html` を共有フォルダの公開場所へコピーする。共有上の旧版は上書き前に退避する。複数人で閲覧している場合は事前に更新時間帯を決める。
8. 共有上の閲覧用HTMLを開き直し、版・プロジェクト・拠点を確認する。
9. 「別の場所で変更されています」と表示されたら、他に編集している人がいないか確認してから「読み込み直す」か「上書きする」を選ぶ。

## 復旧

1. 片方だけの更新、破損、版不一致があれば公開を止める。
2. `data\archive\` から同じ版の旧JSONと閲覧HTMLを対で戻し、閲覧HTMLは共有へもコピーし直す。
3. 編集ツールで旧JSONを読み込み、検証結果と版を確認する。閲覧HTMLを開き直して同じ版であることを確認する。
4. 直前版を少なくとも1組残す。保持期間・廃棄・ダウンロード先は社内規則に従う。

## 配布先で行う受入

自動確認済みの範囲は [実装・検証記録](implementation.md) を参照。以下は実環境で記録して判断する。

| 要件      | 手順・記録                                                                                                                                                                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01     | 調査用ホストの `launcher\tylan.cmd` から編集画面を開き、JSONを作成・保存できること、共有（UNC・割り当てドライブ・日本語と空白を含むパス）へコピーした閲覧HTMLを社内Edge/Chromeで開けることを確認。PowerShellの実行ポリシーやセキュリティ警告が出た場合はその内容を記録 |
| AC-02     | インターネット遮断下で起動・検索・編集・全出力。開発者ツールのNetworkで `127.0.0.1` 以外への通信なしを確認。別のPCから起動中のPCのポートへ接続できないことを確認                                                                                                       |
| AC-03・04 | 調査用ホストでJSONを作成し、全種類の登録・変更・削除・キャンセル・Undoが自動保存され、ブラウザーの再読み込み後に開き直して復元されることを確認。壊れたJSON・10MiB超・未対応版を開き、既存作業が維持されることを確認                                                    |
| AC-05・09 | 閲覧HTMLの版・公開範囲を確認。除外した固有の値がHTMLソースにないこと、script終端等がテキスト表示されることを確認                                                                                                                                                       |
| AC-06     | 20項目がNo.1〜8・12〜23。新回次は未確認、必須欄・対象別結果・総括・対応完了時の判定維持を確認                                                                                                                                                                          |
| AC-07     | examples/network.jsonで階層・グループ・不明端点・冗長配線・検索・絞り込み・固定・配置復元・全体/表示範囲PNG・印刷を確認                                                                                                                                                |
| AC-08     | IP重複・DHCPの重なりは警告付きで保存でき、参照切れ・ポートの二重利用は拒否されることを確認                                                                                                                                                                             |
| AC-09     | 社内Excelで日本語CSV・引用符・改行・式開始文字の無害化を確認。CSVからの復元は行わずJSONを使う                                                                                                                                                                          |
| AC-10     | 標準PCで10拠点・1,000機器・2,000接続・5,000監査結果を用意。初回5秒・検索1秒・300ノード/600エッジの操作目標を測定し、端末・回線・データ・測定結果を記録。1366×768、長い名称、キーボードも確認                                                                           |
| AC-11     | 編集中のJSONを別のプロセス（エディター等）で変更し、自動保存が止まって上書きされないことを確認。その後、前回の監査のJSON・閲覧HTMLへ戻して版の対応を確認                                                                                                               |
| AC-12     | 実際の閲覧アカウントで共有上の閲覧HTMLを読め、上書きできないことを共有/NTFS権限で確認。正本JSON・証跡を共有に置いていないことを確認                                                                                                                                    |

アプリ内認証・排他ロック・自動的な秘密検出・正本への直接上書きは行わない。パスワード・PSK・秘密鍵・資格情報を備考や証跡にも記入しない。

## 現地監査の受入（現地ゲート）

自動検証の範囲は [自動収集計画12章](audit-automation.md#12-実装検証の対応表2026-11-09) を参照。以下は実機・実LANでしか確認できないため、2026-11-09時点で未実施である。実LANの走査は通常のCIに含めず、許可を得た範囲で行う。

### 事前準備

1. 調査用ホストで `bun run verify` が通ることを確認する。
2. 調査用ホストにPython 3.12・Nmap・Wireshark（TShark）・Npcapを導入し、版を記録する。監査画面に不足ソフトの表示が出ないことを確認する。
3. `data\evidence\` を調査担当者以外が読めないことを確認する。詳細証跡（DNS問い合わせ名）を使う場合は保持期限と廃棄手順を決める。

### 現地で確認する項目

| ゲート | 手順                                                                                                                                                                         | 合格条件                                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| G1     | 標準モードで対象CIDR・除外を設定して実行。別NICの観測点（ミラーポート等）で調査ホストの送信を観測。VPN接続中・同一CIDR内の/32経路・別NIC優先・実行中のNIC切断/経路変更も試す | 選択NIC・送信元以外から送信しない。除外IPへ送らない。経路違反は開始前に拒否、実行中の変更は停止し部分完了と表示する            |
| G2     | Npcap未導入・権限不足・正常の各状態でTSharkを実行。IPv6のDNS/DHCPv6/NS/NA/RAを流した状態で観測。負荷をかけてドロップを発生させる                                             | 権限不足は「権限不足」、0件は「0件」と表示。IPv6の通信を取り込まない。ドロップ件数（取得できなければ「取得不能」）が表示される |
| G3     | 日本語・空白を含むパスを `-Root` に指定して起動し、保存・証跡転送・取り込みを行う。取り込み中に書込権限を外す、置換を妨げる、tylanを強制終了する                             | 失敗時に正本が壊れず「保管済み」と誤表示しない。ローカル結果が残り、再起動後に照合から再開できる                               |
| G4     | 詳細調査でAD（OU限定）・DHCPサーバー・Windows端末の読取を実行。権限のない対象を混ぜる                                                                                        | 権限不足の対象だけが失敗し、他の収集は続く。WinRM・FWの設定を変更しない                                                        |

記録には実施日、担当者、拠点、対象範囲・除外、NIC・送信元・経路、ツールとOSの版、作業フォルダ、実測結果、未達事項を残す。人工fixtureやモックの成功で代替しない。
