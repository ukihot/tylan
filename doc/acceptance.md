# 公開・復旧・受入手順

## 配布前

1. 開発端末で `bun install --frozen-lockfile`、`bunx playwright install chromium`、`bun run verify` を実行する。
2. `dist/` の `editor.html`・`tylan.cmd`・`tylan.ps1`、`SHA256SUMS.txt`、`THIRD-PARTY-LICENSES.txt` を確認し、3ファイルを `tools/` に置く。ハッシュ・依存ライセンスを一緒に管理する。
3. 社内管理者の共有HTML実行ポリシーを確認する。ブラウザーの保護設定を無効化して回避しない。

## 日常の更新

1. 編集担当を1名に限定する。
2. 監査の開始時は、`tools/tylan.cmd` を起動し、前回分を引き継いで今回分のJSON（例：`network-2026.json`）を `working/` に作る。前回分のJSONはそのまま残り、記録になる。臨時更新では一覧から今回分を開く。
3. 拠点・資産・配線・設定を登録し、監査回次を作成する。回次は拠点ごとに20項目の未確認から始まる。変更は自動保存される。ヘッダーが「保存済み」であることを確認する。
4. 要対応には問題点・確認者・確認日・対応事項を関連付ける。総括と対象別結果の矛盾は解消する。実環境の異常を示す警告は残してよい。
5. 公開拠点・追加公開項目を選び、プレビューの件数と除外項目を確認する。
6. 「閲覧用HTMLを公開」で `published/viewer.html` を更新する（旧版は自動で `archive/` へ移る）。複数人で閲覧している場合は事前に更新時間帯を決める。
7. 保存した閲覧用HTMLを開き直し、版・プロジェクト・拠点を確認する。
8. 「別の場所で変更されています」と表示されたら、他に編集している人がいないか確認してから「読み込み直す」か「上書きする」を選ぶ。

## 復旧

1. 片方だけの更新、破損、版不一致があれば公開を止める。
2. `archive/` から同じ版の旧JSONと閲覧HTMLを対で戻す。
3. 編集ツールで旧JSONを読み込み、検証結果と版を確認する。閲覧HTMLを開き直して同じ版であることを確認する。
4. 直前版を少なくとも1組残す。保持期間・廃棄・ダウンロード先は社内規則に従う。

## 配布先で行う受入

自動確認済みの範囲は [実装・検証記録](implementation.md) を参照。以下は実環境で記録して判断する。

| 要件      | 手順・記録                                                                                                                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01     | UNC・割り当てドライブ・日本語と空白を含む共有パスの `tylan.cmd` から編集画面を開き、JSONを作成・保存できること、生成した閲覧HTMLを社内Edge/Chromeで開けることを確認。PowerShellの実行ポリシーやセキュリティ警告が出た場合はその内容を記録 |
| AC-02     | インターネット遮断下で起動・検索・編集・全出力。開発者ツールのNetworkで `127.0.0.1` 以外への通信なしを確認。別のPCから起動中のPCのポートへ接続できないことを確認                                                                          |
| AC-03・04 | 実際の共有パスでJSONを作成し、全種類の登録・変更・削除・キャンセル・Undoが自動保存され、ブラウザーの再読み込み後に開き直して復元されることを確認。壊れたJSON・10MiB超・未対応版を開き、既存作業が維持されることを確認                     |
| AC-05・09 | 閲覧HTMLの版・公開範囲を確認。除外した固有の値がHTMLソースにないこと、script終端等がテキスト表示されることを確認                                                                                                                          |
| AC-06     | 20項目がNo.1〜8・12〜23。新回次は未確認、必須欄・対象別結果・総括・対応完了時の判定維持を確認                                                                                                                                             |
| AC-07     | examples/network.jsonで階層・グループ・不明端点・冗長配線・検索・絞り込み・固定・配置復元・全体/表示範囲PNG・印刷を確認                                                                                                                   |
| AC-08     | IP重複・DHCPの重なりは警告付きで保存でき、参照切れ・ポートの二重利用は拒否されることを確認                                                                                                                                                |
| AC-09     | 社内Excelで日本語CSV・引用符・改行・式開始文字の無害化を確認。CSVからの復元は行わずJSONを使う                                                                                                                                             |
| AC-10     | 標準PCで10拠点・1,000機器・2,000接続・5,000監査結果を用意。初回5秒・検索1秒・300ノード/600エッジの操作目標を測定し、端末・回線・データ・測定結果を記録。1366×768、長い名称、キーボードも確認                                              |
| AC-11     | 編集中のJSONを別のPCで変更し、自動保存が止まって上書きされないことを確認。その後、前回の監査のJSON・閲覧HTMLへ戻して版の対応を確認                                                                                                        |
| AC-12     | 実際の閲覧アカウントでpublishedの読取ができ、working・published・toolsの上書きができないことを共有/NTFS権限で確認                                                                                                                         |

アプリ内認証・共有上の排他ロック・自動的な秘密検出・正本への直接上書きは行わない。パスワード・PSK・秘密鍵・資格情報を備考や証跡にも記入しない。
